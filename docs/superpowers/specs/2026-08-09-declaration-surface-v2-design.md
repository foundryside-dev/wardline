## 1. Scope

Extend wardline's declaration surface — today exactly three function-level decorators — to carry five new declaration kinds, so the admission-test-passing slice of the designed-but-unbuilt annotation groups (as-built spec §10) becomes buildable:

1. **Schema contracts** — per-source, per-field three-state classification enabling WL-001 (`PY-WL-127`) and WL-002 (`PY-WL-128`).
2. **Sensitivity marks** — values/fields that must not reach disclosure sinks; also the per-field "may never be defaulted" mechanism for contracts.
3. **Facets** — audit-primacy (and, later, operation-semantics) markers enabling WL-005.
4. **Restoration boundaries** — evidence-based declarations producing the two reserved lattice states `UNKNOWN_ASSURED` / `UNKNOWN_GUARDED`.
5. **Dependency-taint declarations** — caller-granted claims about third-party call returns.

### 1.1 Non-goals (unmissable version)

- **No governance apparatus** — no reviewer identity, approvals, expiry *adjudication*, or ratification anywhere in wardline; that is legis's jurisdiction and wardline stays "No governance". Mechanical expiry-lapse (a lapsed entry stops taking effect and resurfaces, the shipped waiver pattern) is not adjudication and is permitted. No declaration format carries a `reviewed_by`-style identity field.
- **No runtime structural layer and no type-system layer** — the surface remains static-analysis markers that are runtime no-ops.
- **The existing three markers' signatures are frozen** — `@external_boundary`, `@trust_boundary`, `@trusted` gain no arguments, ever (§4.3 is why).
- **No contract inheritance** — a `Contract` cannot extend or compose another contract in v1; every contract states its fields in full. Deliberate surface-minimalism; revisit only with real duplication evidence.
- **No field-sensitive taint** — labels carry mapping-level identity only.
- **No new Rust declaration surface** — the Rust frontend recognises none of the new vocabulary, and its legal-state sets are **unchanged** (§4.4): Rust cannot produce restoration states in this program.

## 2. Design principles

**P1 — Obligation vs exemption decides the grant axis.** A declaration that creates *obligations the engine checks* (required fields, audit-primacy, sensitivity marks) lives in source and needs no grant — the review of the declaration is the review of the code, in the same diff. A declaration that grants *exemptions or uplift the engine honours* (dependency-taint; any future restoration uplift past the cap; any future consumption of record-only tokens) is caller-granted, and its state caps are enforced at the parser regardless of grant. Net new grant flags in this program: **one** (§9).

**P2 — A declaration may reduce a finding's severity, never its existence (D1).** The three shipped suppression channels act on findings that already exist, which is what lets the gate evaluate a separately built unsuppressed population. A contract acts *before* finding generation — upstream of that split — so contract-driven suppression would be the only repo-authored channel with full gate authority by default. Therefore: a matching approved default **downgrades to INFO**; it never removes the finding. No declaration of any kind in this program silences an existing rule (this binds sensitivity unmarking too, §6).

**P3 — One readability rule for the entire surface.** The analyser reads exactly **five** forms, everywhere:
1. a **literal constant** (`"OFFICIAL"`, `42`, `True`, `None`) — `ast.Constant`;
2. a **value token**: a namespaced attribute whose receiver alias-resolves to an exact known export (`Field.REQUIRED`, `Evidence.STRUCTURAL` — the existing `TaintState.ASSURED` discipline). Bare names are rejected in value positions, **except exactly as form 5 permits** — outside form 5's builtin LEVEL slot on a module-top-level `def`, and outside its same-file, single-binding, one-hop discipline, a bare name in a value position remains rejected;
3. a **constrained marker call** whose callee is an exact known export and whose every argument (positional or keyword, including tuple elements) is one of forms 1–3, recursively (`Field.default("OFFICIAL")`, `Field.default("OFFICIAL", sensitivity=(Sensitivity.of("classification"),))`) — recursion is bounded by the AST and each level fail-closes independently;
4. a **declaration reference**, legal only in an argument slot typed `RefArg` (§4.2): a bare `Name` or dotted `Attribute` that alias-resolves to a **module-level declaration assignment** (`NAME = Contract(<forms 1–3 only>)`, direct top-level, single-`Name` target, unconditional, not rebound). This is the one place a bare name resolves **across modules**, because a reference *must* be indirected to be shared — and it resolves through the import system, so a typo is an `ImportError` and a rename is refactorable. Form 5 is same-file for a different and independent reason — §14's cache and determinism facts — not because it merely lacks this backing;
5. a **value reference**, legal only in an argument slot typed `LevelArg` on a **builtin** marker (§4.2), and only when the decorated `def` / `async def` is a **direct element of the module body** — a stricter test than "evaluated in module scope", so a `def` or `async def` nested inside a module-level `if` or `try` is out too (§4.2.1): a bare `Name` — **never a dotted `Attribute`**, which stays form 2 — that resolves to a **module-level value assignment in the same file** (`_SVC_LEVEL = "ASSURED"`, `_SVC_LEVEL = TaintState.ASSURED`; direct top-level, single-`Name` target, unconditional, not rebound anywhere in module scope, and lexically preceding the decorated `def` / `async def`), and whose right-hand side is itself form 1 restricted to a `str` constant — a non-`str` constant is never coerced — or form 2. **The reference site is restricted as tightly as the binding site**: a decorator expression is evaluated in the enclosing class or function scope, so a bare `Name` in a LEVEL slot on a **method, or on a nested `def` / `async def`, is unreadable** whatever the module holds — and the cut is drawn one notch tighter still, at the module body itself, so a **conditionally-defined `def` / `async def`** is unreadable too even though it introduces no new scope (§4.2.1 gives the reason and the verdict). Where this specification writes **"a module-top-level `def`"** as shorthand, it means exactly this test — a `def` **or `async def`** statement that is a direct element of the module body — and never the looser "no enclosing `ClassDef` or `FunctionDef`". The test is **evaluated from the per-module census**, which records those statements by node identity (§4.2.1), and never from an implementer's proxy such as a column offset or a qualname shape. **One hop, never a chain**: a right-hand side that is another bare name is unreadable, mirroring form 4's own refusal to chain (`NAME = Contract(<forms 1–3 only>)`). Resolution is **same-file only** (§14 records why, and the one precondition that would reopen it), so the DRY refactor is bought without buying a cross-module cache-invalidation obligation. Every other right-hand-side shape — a call, an f-string, a subscript, a conditional expression, a tuple, `os.environ[...]` — is unreadable and observable, never guessed (§4.2.1).

A declaration that is partially readable is **wholly unreadable** and fails loud (§5.2's `UNREADABLE` label state; §10's rules) — never partially honoured. **LEVEL-position unreadability takes a different route to observability, and there are exactly three routes in all.** A **builtin** marker's unreadable LEVEL value is *not* routed to §5.2's `UNREADABLE`: that is a value-label-plane state — uncached, never `FunctionSummary` (§3) — and its algebra ships in S2 (§13.2), whereas a level sits on the cached L1 seed plane. Such a value takes the `WLN-ENGINE-UNREADABLE-MARKER-VALUE` FACT instead (§4.2.1) — **provided the marker call's own shape is valid**, the shape gate being decided first and short-circuiting the value reader entirely (§4.2, and §4.2.1's case table). A **custom** `BoundaryType`'s unreadable level value is unchanged by revision 6: it keeps `WLN-ENGINE-UNPROVABLE-BOUNDARY` and an `UNKNOWN_RAW` seed (§4.2's compatibility boundary), and never also takes the new FACT. Every other unreadable declaration — every non-LEVEL argument kind — keeps §5.2's `UNREADABLE`. The new FACT is `Severity.NONE`, so the honest statement about it is *observable*, not *gating*: the seed still drops and the tier-modulated rules still go quiet, which is precisely why its five soundness conditions are normative rather than advisory.

**P4 — New axes are new types with empty defaults; runtime signatures and serialized S0 contracts stay frozen.** S0 promotes the existing `LevelArg` reader into the shared public engine-floor `marker_reader` and tightens analyzer call-shape handling to agree with the three frozen runtime decorator signatures. It does not change those signatures, descriptor bytes, or the builtin provider fingerprint. Every new field on `SeedResult`/`FunctionTaint`/`FunctionSummary`/`AnalysisContext` defaults empty. The frozen S0 contracts named here are the runtime signatures, the descriptor bytes and the builtin provider fingerprint, and **revision 6 leaves that frozen list unamended**: the residual-FACT carrier is a new, empty-defaulting `SeedResult` / `FunctionSeed` field that is **not** serialised, so the internal summary-cache schema does not move either (§4.2.1, §4.3). Shipping gate: on a declaration-free tree, the byte-identity golden corpus has a **zero-byte delta** and requires no regeneration.

**P5 — Labels are not taint.** Contract identity and sensitivity ride a parallel side-channel (§5.2), never `var_taints`, never `combine()`/`least_trusted`, and never `FunctionSummary` — labels are recomputed fresh every scan, so a stale cache structurally cannot produce a false-green WL-001. (The single exception is the restoration **witness**, which is taint provenance, not a label — §8.3.)

**P6 — Every declaration is a ledger entry, and consumers upgrade first.** Every declaration kind emits into one deterministic inventory (§11.1) built by a single factory and consumed by attest, assure/dossier, and the legis artifact. Cross-product contract changes (vocabulary version, attest schema, legis wire) follow **consumer-first dual-read**: the consumer learns to accept both versions, with the contract-appropriate preview artifact and coordinated receipt, before wardline emits the new one (§13.1).

**P7 — Every group ships with the metric that proves it is live, in the same change.** Per-kind declaration counts enter the resolution posture and the signed attest payload; the inertness machinery gains per-group arming (§11.4).

### 4.1 weft-markers — staged, consumer-matched releases

All exports: runtime no-ops, **strictly keyword-only call forms**, zero-dependency, Python-3.9 floor (frozen dataclasses without `slots`; `class Evidence(str, Enum)`-style tokens).

### 4.2 Marker-argument grammar (engine floor)

Three argument kinds drive the generic reader (the registry encodes them as `ArgKind.LEVEL` / `ArgKind.TOKEN_SET` / `ArgKind.REF` — one concept, declaration-class name and registry enum name); each is fail-closed on any deviation:

- **`LevelArg`** — S0 promotes the shipped AST reader to the shared engine floor without widening its accepted level-token **domain**. *Domain* here means the set of accepted token **values** — the `TaintState` members each `BoundaryType.level_args` entry declares as `allowed` — and not the set of syntactic forms that may spell one; that distinction is what revision 6 turns on, and no reader may take this sentence as forbidding it. **Revision 6 widens the forms and leaves the values exactly where they were**: P3 form 5 admits a same-file module-level value reference in a **builtin** marker's LEVEL slot, on a **module-top-level `def`** only (§4.2.1 states both restrictions and the cases they refuse). The reader still allow-checks the resolved token against the argument's `allowed` set before returning, so the worst case of a wrongly-resolved LEVEL is a state already reachable by writing the literal (for `@trusted`: `{INTEGRAL, ASSURED}`) — a widened form cannot mint a lattice state. Declared sibling arguments are legal; an undeclared keyword or extraction defect makes a custom level-bearing declaration unprovable rather than partially readable. No ignored or compatibility keyword path exists.
- **`TokenSetArg`** — a tuple of value tokens from a declared set (`evidence=`, `marks=`). Any non-token element, any bare name, any positional arg → unreadable. **P3 form 5 is scoped to `ArgKind.LEVEL` and does not reach this argument kind**, nor `RefArg`: a bare name in place of the tuple, or inside it, stays unreadable. The scoping is by argument kind rather than by marker name **within the builtin registry** — it is not a route into `BoundaryType.level_args` on a custom pack, which revision 6 leaves exactly as released. Its purpose is to catch `to_level=` on `@trust_boundary`, which is builtin and has the identical hole, under the same sentence that covers `level=` on `@trusted`, so no second frozen marker is left behind. "Covered by the same sentence" means covered on the same terms, not covered everywhere: `to_level=` on `@trust_boundary` is subject to form 5's module-top-level `def` restriction like any other LEVEL slot, so a bare `Name` in that slot on a **method, a nested `def` / `async def`, or a conditionally-defined `def` / `async def`** remains unreadable (§4.2.1). The refusal to widen `TOKEN_SET` is a soundness argument first and a sequencing argument second: `TOKEN_SET`'s first real consumer is `evidence=` on `@restoration_boundary`, which **can** mint the reserved `UNKNOWN_ASSURED` / `UNKNOWN_GUARDED` states, so an indirection here would widen the producer of a security invariant rather than a bounded, already-reachable set; and container resolution (may the tuple itself be a reference, or only its elements?) is a second, larger grammar question already owned by P11b's S2 domain-integration gate (§12).
- **`RefArg`** — a declaration reference (P3 form 4). Resolves via the existing alias map to a module-level declaration FQN; the referenced assignment is read by the shared declaration reader. Unresolvable, ambiguous, conditional, rebound, or shadowed-root reference → `UNREADABLE` (§5.2), never silence.

S0 registers all three `ArgKind` tags so the registry shape is stable, but only `LEVEL` has a live consumer in S0. The generic `REF` and `TOKEN_SET` readers ship in S2 with their first consuming markers; later token domains reuse the same `TOKEN_SET` reader and repeat their own domain-integration gate.

**Positional arguments are illegal on every marker in the new vocabulary**, and on the existing three (`PY-WL-130`, §4.3). Canonical forms:

```python
@schema(contract=ORDER_CONTRACT)          # RefArg, keyword-only
@sensitive(marks=(Sensitivity.PII,))      # TokenSetArg
@restoration_boundary(evidence=(Evidence.STRUCTURAL, Evidence.INTEGRITY))
@audit_record                             # bare form, no call
```

`RegistryEntry` carries the whole builtin call grammar as three registry-owned properties: `kwargs: frozenset[str]` (the declared keyword set per marker), `arg_kinds: Mapping[str, ArgKind]` (the reading discipline per declared keyword), and `call_form: MarkerCallForm` ∈ {`BARE_ONLY`, `CALL_ONLY`, `BARE_OR_CALL`} (whether the marker is legal bare, called, or either). The shipped three mirror their frozen runtime signatures: `@external_boundary` is `BARE_ONLY` (`external_boundary(fn)`), `@trust_boundary` is `CALL_ONLY` (`trust_boundary(*, to_level)`), `@trusted` is `BARE_OR_CALL` (`trusted(fn=None, /, *, level=INTEGRAL)`).

Registry entries are immutable snapshots; `arg_kinds.keys() == kwargs`; no ignored or compatibility keyword category exists. The load-time tripwire covers both builtin roots and requires every builtin `BoundaryType.level_args` schema to equal the registry keyword set with `LEVEL` kinds.

A call-form violation is a call-**shape** offence like every other — `call_not_allowed` for a called bare-only marker, `call_required` for a bare call-only marker — and one shared validator decides every shape offence. Call form is decided first, so a called `BARE_ONLY` marker is `call_not_allowed` whatever it carries. Otherwise the validator reports positional arguments, extraction offences in source order, keyword classification and duplicate events in source order, then missing names in sorted order; it does not emit a missing-name offence when an unreadable splat might supply that name. The stable reason vocabulary is `call_not_allowed`, `call_required`, `positional_args`, `invalid_splat_key`, `unreadable_splat`, `undeclared_kwarg`, `duplicate_kwarg`, and `missing_kwarg`; `PY-WL-130` emits one finding per offence in this deterministic order. The reader and `PY-WL-130` consume that one verdict, so a rule can never disagree with seeding about a shape. **Value problems are not shape problems, and shape is decided first**: an unreadable value (`level=get_level()`) **on a call whose shape is valid** is the reader's fail-closed `None` — no seed, and from revision 6 the `WLN-ENGINE-UNREADABLE-MARKER-VALUE` FACT rather than silence (§4.2.1) — and a readable-but-invalid token (`level='ASURED'`) is `PY-WL-114`'s DEFECT; neither is a shape offence. **The shape gate short-circuits, and the specification states that ordering rather than leaving it implicit in a task's step order:** `call_shape_offences` is the one shape verdict and it runs *before* any level is read, so a marker whose shape is malformed drops its seed at the shape gate, takes `PY-WL-130`, and never reaches the value reader. A site that is **both** shape-malformed and value-unreadable therefore takes `PY-WL-130` alone and no residual FACT (§4.2.1 states the case, and checks the five soundness conditions against it). `level=CFG` is no longer an instance of the first case when `CFG` satisfies P3 form 5 in full on a **shape-valid** builtin marker call — a builtin marker, a valid call shape, a module-top-level `def`, and a single qualifying module-scope binding: it resolves, and if what it resolves to is an invalid token it becomes the second case. Where any of the form-5 conditions fails, `level=CFG` stays the first case and takes the FACT — **unless the call's own shape is malformed, in which case the shape gate has already short-circuited, `PY-WL-130` is the channel, and no residual FACT is emitted at that site**.

**The statically readable keyword grammar.** Direct keywords and **literal** `**{...}` dict splats are readable. One literal dict is normalised with Python's own insertion-order/last-value semantics before its items count: repeated keys *within a single literal dict* are legal Python and the last value wins, while a direct-keyword/literal-splat collision on the same name is a `duplicate_kwarg`; a non-string literal key is `invalid_splat_key`. A **dynamic** `**mapping` — any splat whose value is not a literal dict, and any nested `**` inside one — is outside the statically readable declaration grammar: it may be perfectly valid at runtime, but wardline cannot statically prove it satisfies the declaration, so the seed drops and the diagnostic states that analyzer limitation. Diagnostics stay truthful: `PY-WL-130` calls a shape runtime-invalid only for a proved runtime-invalid reason, and `unreadable_splat` says only that wardline cannot statically read the mapping.

**Builtin/custom compatibility boundary.** Registry call-form validation and `PY-WL-130` apply only to builtin markers. Custom `BoundaryType` packs retain their released `level_args` contract. An unreadable custom level value or foreign metadata on a level-bearing custom marker takes the `WLN-ENGINE-UNPROVABLE-BOUNDARY` FACT channel and seeds `UNKNOWN_RAW`; it never becomes `PY-WL-130`. A custom type with no level arguments may carry foreign metadata kwargs that Wardline ignores and may still seed. **Revision 6 changes nothing on this side of the boundary.** P3 form 5 is builtin-only: a custom `BoundaryType`'s `level_args` keep their released reading contract, an unreadable custom level value keeps `WLN-ENGINE-UNPROVABLE-BOUNDARY` and `UNKNOWN_RAW`, and it **never also** takes `WLN-ENGINE-UNREADABLE-MARKER-VALUE` — the new FACT is builtin-only too, so no unreadable value is ever reported on two channels or counted twice in `decorator_coverage` (§4.2.1).

#### 4.2.1 Form 5 — the same-file value reference and its residual channel (revision 6)

`@trusted(level=_SVC_LEVEL)`, with `_SVC_LEVEL = TaintState.INTEGRAL` at module top level, is an ordinary DRY refactor to a module constant. Under revisions 1–5 the reader returned `None`, the seed dropped, the function silently left the declared set, and every tier-modulated rule went quiet on it: with the level written literally the repro yields two active ERROR DEFECTs and exit 1, and with it named it yields zero active findings and exit 0 (`wardline-2b2a6cddfa`, reproduced). Revision 6 closes that hole on PDR-0018's authority — **the reader resolves the reference, and everything that stays unreadable becomes observable rather than silent**. Both halves ship; neither substitutes for the other.

**Resolution is a binding census over module scope, never a last-write-wins walk.** The obvious implementation template — the shipped module-level global raw-seed walker (`collect_module_global_raw_seeds`) — carries last-binding-wins semantics, and last-binding-wins in a *value* position is a trust escalation, because decorator evaluation order is not module source order. Form 5 therefore takes **form 4's discipline, extended by three clauses form 4 does not carry**. Inherited unchanged: direct top-level, single-`Name` target, unconditional, **not rebound**. Added by form 5: **lexical precedence** — the binding must precede the decorated `def` / `async def` in source order; a **module-scope census** wider than the set of bindings form 4 inspects; and a **reference-site restriction** — form 4 constrains only where a name may be *bound*, whereas form 5 also constrains where it may be *read*, to a decorated `def` / `async def` that is a direct element of the module body (below). The census is what carries all three of these clauses: it is built once per module and records the qualifying bindings with the line each is bound at **and** the qualifying reference sites, so one build answers all three.

**The census enumerates every binding occurrence of the name in module scope, at any statement depth** — not only direct top-level statements. Occurrences nested inside `if` / `try` / `with` / `if TYPE_CHECKING:` bodies count; so do `import` and `from … import` bindings, `for` targets, `with … as` targets, `except … as` targets, walrus assignments (`:=`), and augmented assignments (`+=`). **The list also carries every module-scope binder that is not an assignment statement** — `def <name>`, `class <name>`, `del <name>`, and `match` capture patterns — because omitting them runs **fail-open**: a name the census does not know is rebound looks singly-bound, and form 5 would resolve a token the code has since replaced with a function, a class, or nothing at all. A name resolves **only when exactly one of those occurrences satisfies the direct-top-level, unconditional, single-`Name`-target discipline, no other module-scope occurrence of any kind exists, and that one occurrence precedes the decorated `def` / `async def` lexically**. A qualifying top-level binding paired with a *conditional* module-scope rebinding is therefore unreadable, not resolved to the top-level one: resolving it would silently pick whichever of the pair is the more trusted, which is exactly the trust escalation last-binding-wins was refused to avoid.

**Class and function bodies are separate scopes and do not enter the census** — and that omission is only sound because of two other refusals stated immediately below. First, form 5 applies only when the decorated `def` / `async def` is itself a direct module-top-level statement, so a class-body binding can never be the one Python evaluates at decoration time. Second, **the presence of any `global <name>` statement anywhere in the module makes that name unreadable for form 5** — a cheap fail-closed rule that needs no interprocedural reasoning and covers every nested-scope write back into module scope. Remove either refusal and the omission becomes a false green.

**The reference site is restricted, not only the binding site: form 5 requires a module-top-level `def` / `async def`.** Python evaluates a decorator expression in the **enclosing class or function scope** at `def` time, never in module scope. Given `TO = "GUARDED"` at module top level and `TO = "ASSURED"` in a class body, `@trust_boundary(to_level=TO)` on a method of that class denotes the class-body binding; an engine that resolved the module-level one would seed a level the code does not declare, with no diagnostic on any channel — a new false green of the exact class this revision closes, and demonstrated in both directions (the over-trusting pairing downgrades ERROR to WARN through the severity model and exits 0 on unchecked code; the reverse pairing over-severs and threatens PRD-0003 criterion 3). Form 5 therefore applies **only when the decorated `def` / `async def` is a direct element of the module body** — that is, the `def` or `async def` statement is itself an entry in `Module.body`. **The test has one evaluation point and it is the census**: the per-module census records the module's form-5-eligible reference sites by node identity (see the engineering constraints below), and both readers answer this restriction by asking whether the reference site they were handed is one of them. This is the single test, and the gloss is the same test rather than a looser paraphrase of it: **"a direct element of the module body" is strictly narrower than "no enclosing `ClassDef` or `FunctionDef`"**, and the two disagree on exactly one realistic shape — a `def` or `async def` nested inside a module-level `if` or `try` (a `sys.version_info` fork, or `if TYPE_CHECKING:`). That shape introduces no new scope, so the scope-substitution hazard above does not reach it; the narrower test refuses it anyway, and the specification states the verdict plainly rather than leaving the two readings to disagree: **a conditionally-defined module-level `def` / `async def` is unreadable and takes the residual FACT**. The tighter cut is chosen for two reasons — it fails closed, and it matches the census's own "direct top-level, unconditional" discipline word for word, so the binding site and the reference site are governed by one sentence rather than two that can drift apart. A bare `Name` in a LEVEL slot on a method, on a nested `def` / `async def`, or on a conditionally-defined `def` / `async def` is therefore **unreadable** and takes the residual FACT. §14 records the enclosing-scope walk as a rejected alternative with its named reopening precondition. **The measured cost recorded in §14 covers the method-and-nested-def cut only** — 6 of 72 marker call sites, every one of them a method or a nested def, with zero bare-`Name` level values anywhere in the repository. **That measurement does not cover the conditional-`def` cut and must not be read as covering it**: it is silent on how many module-level `def` / `async def` statements sit inside an `if` or `try`, because the census never counted that population. The conditional-def cut is therefore taken on the fail-closed argument alone, not on a cost figure, and §14's reopening precondition covers it on the same terms.

**Form 5 is builtin-only.** It resolves only for a **builtin** marker's `ArgKind.LEVEL` argument. A custom `BoundaryType`'s `level_args` are **unchanged** by revision 6 (§4.2's builtin/custom compatibility boundary): an unreadable custom level value continues to take the `WLN-ENGINE-UNPROVABLE-BOUNDARY` FACT and seed `UNKNOWN_RAW`, and it **never also** takes `WLN-ENGINE-UNREADABLE-MARKER-VALUE`. One unreadable value takes exactly one channel, never both — which is what keeps the residual FACT from double-emitting and keeps condition 5's `decorator_coverage` count from double-counting the same site.

**Every case has a stated answer.** An unstated case becomes an implementer's guess, and in this engine a guess becomes a silent false green — the exact defect this revision closes. **The verdict vocabulary is uniform, and each verdict names its channel exactly once:** `RESOLVES` (a seed is produced), **`UNREADABLE + FACT`** (no seed, and `WLN-ENGINE-UNREADABLE-MARKER-VALUE` is emitted — every unreadable builtin LEVEL value **on a shape-valid call** takes it, with no exceptions and no rows that leave it implicit; where the call's own **shape** is malformed the shape gate has already short-circuited and `PY-WL-130` is the channel, which the table's last row states), and `READS, then rejects` (the value was read, so the louder `PY-WL-114` DEFECT is the channel and the residual FACT is not). **Two rows are not form 5 at all**, and they are not disposed of the same way. A **dotted `Attribute`** in the LEVEL slot stays form 2 and is adjudicated on form 2's own terms — still inside the vocabulary above, because it is still a builtin LEVEL value. A **custom `BoundaryType`**'s LEVEL argument leaves that vocabulary entirely and names its own released channel instead.

Engineering constraints, each normative:

- **Form 5 is a bare `Name` only, explicitly not a dotted `Attribute`.** Form 4 admits both, so a reader will assume form 5 mirrors it; it does not, and the constraint is pinned in the form-5 text itself (P3) rather than in a footnote, because `PY-WL-114`'s shipped clean examples included `@trusted(level=cfg.LEVEL)` and mirroring form 4 would have changed its behaviour. That example is removed outright by this revision (see the consequences below), which is a separate obligation and not a substitute for this one.
- **Form 5 attaches to the shared public engine-floor `marker_reader` (the `ArgKind.LEVEL` path), never to either of the two current reader copies, and lands only after they are unified.** The two copies are the provider's `_level_token` / `_read_level` in `decorator_provider.py` and `PY-WL-114`'s own `_level_token` in `invalid_decorator_level.py`. A one-sided widening mints a **new** silent false green of the exact class being closed: with the provider widened and the `PY-WL-114` copy not, `_SVC_LEVEL = "ASURED"` resolves in the provider, `TaintState()` raises, the seed drops — while the rule copy sees a bare `ast.Name`, returns `None`, and skips the site. Silent on every channel.
- **The provider's form-2 semantics are the ones that survive unification — the two copies disagree today, on exactly the right-hand side form 5 depends on.** The provider's `_level_token(value, alias_map)` accepts an `Attribute` only when its receiver **alias-resolves** to the exact FQN `wardline.core.taints.TaintState`, so a coincidental `cfg.ASSURED` is rejected. `PY-WL-114`'s copy takes no alias map and tests the dotted receiver **textually** — `TaintState` or anything ending `.TaintState` — so the two disagree in both directions: `from wardline.core.taints import TaintState as TS` then `TS.ASSURED` reads in the provider and not in the rule, while a project-local class named `TaintState` reads in the rule and not in the provider. The unified reader takes the **provider's alias-resolving semantics**, which are strictly the fail-closed side of both disagreements. This is not a supersession: the delivery plan's frozen interface at line 385 already pins `level_token(value, alias_map)` as *"STRICT: alias-resolved `wardline.core.taints.TaintState` receiver or str literal"* — the specification is stating which of the two live behaviours that frozen signature means, because form 5's right-hand-side allowlist inherits it verbatim.
- **The module census and the reference site are both required parameters** of the shared `level_token` / `read_level` entry points — no default on either — so neither caller can compile without passing both. A defaulted-empty census ships precisely the one-sided false green above, and is forbidden for that reason. The two arrive by different routes, and only one of them carries a defaulting hazard: the **census** reaches the reader through a context object (next constraint), whereas the **reference site** — the decorated `def` / `async def` statement whose decorator is being read — is passed **directly by each caller**, both of which already hold that statement's node when they read one of its decorators: the provider through the entities it seeds, the rule side through the entity's own node. The reference site therefore never rides a context object, and the defaulted-field hazard the next constraint spends a paragraph on does not reach it.
- **A required parameter is not by itself the protection, because the census reaches the reader through a context object, and that is where the forbidden default would live.** The signature discipline binds the *reader*; it cannot bind `AnalysisContext`, whose precedent field `module_bindings` is itself `field(default_factory=dict)` so that direct constructions and tests need not supply it, and which the new field must follow. The forbidden default is prevented at the boundary that actually has it, by two mechanisms stated together. First, **an absent module census and an empty one are different inputs and get different verdicts**, on a predicate the reader can actually evaluate from what it holds: a census that is present but holds no entry for the name — or that does not hold the reference site among its form-5-eligible ones — is an ordinary unreadable and returns `None`, whereas being asked to resolve a **bare `Name` in a LEVEL slot** with **no census present for that module at all** is a plumbing defect rather than an input condition, and the reader **raises**. Stating the trigger that way is what makes it checkable — the reader tests only what it was handed (the value node, the census, and the reference site), never whether some other component ran — and it is also why the defaulted context field above is harmless: a direct construction or test that never presents a bare `Name` never reaches the raise. **Each side has a stated disposition for that raise, and neither is a silent skip.** On the rule side it lands on the shipped per-rule isolation and becomes a gate-eligible `WLN-ENGINE-RULE-FAILED` ERROR DEFECT at the engine path — loud, and impossible to confuse with a clean scan — instead of the silent skip a defaulted empty would produce. On the **provider** side there is no per-rule isolation to land on, and none is wanted: the parse loop's per-file guard catches `SyntaxError`, `UnicodeDecodeError` and `OSError` only, so the raise propagates out of the parse pass rather than being absorbed into a scan result the gate could read green. A plumbing defect that aborts the scan is the acceptable failure here; a plumbing defect that returns a clean scan is the one this whole constraint exists to forbid. Second, **P9 exercises both callers through the analyser's real construction path**, never a hand-built context, so an unplumbed rule side reds the agreement test before it can ship.
- **The census is a structure, not a `Mapping[str, str]`.** A plain name→token mapping cannot express three things this section already makes normative: lexical precedence (which needs the binding's line number), the module-wide star-import poison, and the reference-site restriction (which is about `def` / `async def` statements and not about names at all). The parameter is therefore a **per-module census with three components**. Its first is a **value census keyed by name**, whose entry records either the resolved token or an **unreadable reason**, together with the binding's line. Its second is a module-level `poisoned` flag set by an unresolved star import. Its third is the module's **set of form-5-eligible reference sites** — the `def` / `async def` statements that are direct elements of `Module.body`, held **by node identity** — and it is what gives the reference-site restriction an evaluation point at all. Without it the restriction is normative and unanswerable: `read_level` is handed a **decorator** node and its inner `level_token` only the **value** node, neither of which says which statement is being decorated, and neither caller can re-derive module-body membership from a qualname, because a **conditionally-defined module-level `def` has the same qualname as an unconditional one** — leaving only a column-offset test, which is exactly the implementer's guess this section forbids. **Node identity is sound here because module source is parsed exactly once**: the parse loop parses the module and discovers its entities from that one tree, and the provider and the rule side both receive those same node objects, so the two sides compare against identical objects rather than against equal-looking copies of them. All three components are built **once per module, in the parse loop**, where the tree is already in hand. The unreadable reason is **diagnostic message text, not fingerprint input** — condition 4 below keys the fingerprint on the unparsed value node, which needs no census entry at all, so nothing about the FACT's identity depends on this field. **The census — not either reader — owns the star-import poison predicate and the reference-site predicate alike**, so each is evaluated once per module, in one place, and cannot drift between callers.
- **The census is carried on both context objects, and the rule side addresses it by module.** It rides `SeedContext` for the provider side and `AnalysisContext` for the rule side, and those two contexts are **not the same shape**: `SeedContext` is constructed per file and carries one module's census directly, whereas `AnalysisContext` is project-wide and therefore carries a **mapping from module path to that module's census** — exactly the shape of the shipped `module_bindings: Mapping[str, SinkBindings]` field it follows. "Both callers receive the identical object" is a statement about the **per-module census value**, which is built exactly once per module in the parse loop and then handed to both sides — the provider directly, the rule side as the value under its module key. It is never rebuilt, and no rule computes one: the rule side today holds neither the module AST nor the star-export map, so it literally cannot, and that inability is precisely the pressure that produces the defaulted-empty parameter the constraints above forbid. **That same inability is why the reference-site set rides inside the census rather than being recomputed rule-side**: module-body membership is a fact about `Module.body`, which only the parse loop holds — the rule side holds an entity's own node and can therefore *present* a reference site, but it cannot *classify* one.
- **`shadowed_roots` threads into the value reader, and the form-5 refusal is applied at the census build.** Two placements were available and they give opposite verdicts, so the specification picks one rather than leaving it: applied **where the right-hand side is read** — inside the census build, which is the only place the form-2 receiver is still in view — a shadowed-root right-hand side records an unreadable entry and both readers see the same verdict; applied at the **value's use site** instead — the LEVEL slot itself, not to be confused with form 5's *reference site*, which is the decorated statement — the reader is looking at a bare `Name` whose token has already been resolved, the receiver is gone, and the same code reads as ordinary and resolves. **The census build is the chosen application point.** Separately, `shadowed_roots` still threads into the value reader itself, closing a pre-existing gap for a form-2 value written *directly* in the LEVEL slot: the shadowed-builtin-root set already reaches the marker match on both sides but never reaches the level-token reader, which takes no such parameter today. Revision 6 re-cuts that signature anyway, so this is one parameter, and it closes the surface the widening opens.
- **Binding obligation on the shared-reader task.** The delivery plan freezes the shared reader's produced interface as `level_token(value, alias_map) -> str | None` (plan line 385) and `read_level(..., alias_map=...)` (plan line 388). Neither carries a module-constant source, and neither carries a **reference site** — so as frozen the P9 shared-reader agreement test could not exercise form 5 at all, and two of the eight cases below could not be evaluated by either reader, a decorator node being silent about which statement it decorates. **That task's produced-interface list must be amended to carry the census *and* the reference site — the decorated `def` / `async def` statement, passed directly by the caller — and its CASES table widened**, before P9 can be claimed; the interface as frozen cannot pin P9 as written. The widened CASES table must hold, at minimum, these eight: a **bound** case (a qualifying module-top-level binding, resolving); an **unbound** case (no such name, unreadable); a **method or nested-`def` / `async def` reference site** (unreadable whatever the census's value entries hold, because the census's reference-site set is what decides it); a **conditionally-defined module-level `def` / `async def` reference site** (unreadable — the newest and least obvious of the reference-site rules, and therefore the likeliest to be implemented on one side and not the other); a **two-occurrence census** (unreadable); a **`global`-declared name** (unreadable); a **star-import-poisoned module** (unreadable, every name in the module); and a **custom `BoundaryType` LEVEL argument** (not form 5 — `WLN-ENGINE-UNPROVABLE-BOUNDARY` and `UNKNOWN_RAW`, never the residual FACT). The last two are not optional extras: they are the two cases whose failure mode is **silent cross-reader disagreement** rather than a wrong-but-visible answer — a poison predicate evaluated in one reader and not the other, and a builtin/custom split drawn differently on each side, both produce a channel that fires once or not at all with nothing to compare against. That is exactly what P9 exists to catch. Each case must agree across both readers, which is the property P9 exists to pin — and the **two reference-site cases** are answerable only because the re-cut entry points carry the census and the reference site together; under the frozen signatures those two rows had no input either reader could evaluate them from.

**`WLN-ENGINE-UNREADABLE-MARKER-VALUE` (`Severity.NONE`, `Kind.FACT`) is the residual channel, and it is builtin-only.** It covers what stays unreadable by design in a **builtin** marker's LEVEL slot **on a call whose shape is valid** — a shape-malformed call is short-circuited at the shape gate and takes `PY-WL-130` instead, never both (§4.2; the case table's last row). It does **not** reuse §5.2's `UNREADABLE`, which is type-incompatible on three counts. First, the two states live on **different planes with different carriers**: `UNREADABLE` is a state in the value-label plane's algebra over tracked variables (§3, §5.2), recomputed at L2 and carried on the label side-channel, whereas a level value is an **L1 seed-plane input** consumed at seed time, with no carrier on the label side to hold it. **The distinction is the plane, not the caching** — revision 6's own residual carrier is unserialised (§4.3), so a cached-versus-uncached contrast would prove nothing here and is not the argument. Second, `UNREADABLE`'s definition is written about a *contract* declaration that matched but could not be honoured, with an access-site WL-001 verdict, which has no meaning for a level value. Third, the §5.2 algebra ships in S2, so it does not exist in the S0 engine at all. The FACT copies `RefArg`'s **shape** — "never silence" — substituting itself for the S2-only target. Five conditions are normative; without all five, a fact-only residual is unsound:

1. **Not voided by configuration.** The `untrusted_sources` override rebuilds the `FunctionSeed` with an empty unprovable-boundary tuple unconditionally, so a new field on that same object is erased identically unless the rebuild is explicitly taught to carry it forward. §4.3's existing commitment extends to name this third FACT.
2. **Not inertness-clearing.** Residual entities do not become provider-seeded rows, do not increase `summary.total`, and do not arm or de-inert a scan — mirroring §4.3's unknown-marker contract. Only successful resolution moves the posture denominator.
3. **Not suppressible — and this is structural in the shipped engine rather than something the implementation must add.** Every suppression path keys on `Kind.DEFECT`. `apply_suppressions` (`src/wardline/core/suppression.py`) short-circuits on `if f.kind is not Kind.DEFECT` *before* the baseline / waiver / judged join is consulted at all, and `_is_baselineable_finding` (`src/wardline/core/baseline.py`) admits only `Kind.DEFECT`, so **no waiver, judged entry or baseline row can suppress this FACT, and none can be written for it in the first place**. `SEVERITY_ORDER` likewise omits `Severity.NONE`, so it never gates; a waiver against it would buy nothing and cost the only signal the author gets. **The earlier drafting of this condition borrowed §11.2's *"compared and reported, never suppressible"* baseline-document posture; that borrow is withdrawn as inaccurate.** §11.2 governs the *baseline document's declaration-digest section* — a different object, shipping in S1 — and a `Kind.FACT` finding is not compared-and-reported there, because it never enters the document at all. The obligation this condition places on the implementation is therefore a **guard, not a feature**: a regression pinning that the FACT survives `apply_suppressions` unchanged when a baseline **and** a waiver both carry its fingerprint, so a later refactor of that `Kind.DEFECT` short-circuit cannot break the condition silently.
4. **Distinct fingerprint, computed with the shipped helper — no new one is obliged.** "Unresolved identifier text" is undefined for a call, an f-string or a subscript, so the fingerprint is specified mechanically instead. It is `sha256` over the shipped NUL-join of ordered parts — `pipeline._fp` — and it **mirrors the sibling FACT's part-shape exactly**, that sibling being `_fp("WLN-ENGINE-UNPROVABLE-BOUNDARY", ent.qualname, boundary)`. The parts are **`(rule id, qualname, argument name, unparsed value text)`** and there is no fifth: in particular there is **no relpath part**, because the sibling carries none and the qualname already scopes the site — stated so an implementer does not invent a fourth component to a three-part precedent. `ast.unparse` of the value node supplies the last part, and the two treatments named below apply **to that part alone, before it becomes a part**, never to the joined preimage. Both halves of "normalised and truncated" are named rather than left to the implementer. *Normalised* is **NFC**, following §11.1's declarations-digest encoding — the same normal form for the same reason, so two spellings of one identifier cannot mint two fingerprints; layout normalisation needs no separate rule because `ast.unparse` already emits canonical spacing, which is what makes the fingerprint reformat-stable. *Truncated* is **200 characters, measured after normalisation**, which bounds the key for a pathological value expression; the admitted cost is that two distinct values sharing a 200-character prefix collide into one fingerprint, acceptable here because the channel is `Severity.NONE` and never gates, and because the argument name is part of the key. **This does not breach §12's P8, and the two are about different objects:** P8 forbids delimiter-joined and truncated **preimages** for the *provider fingerprint*, which is a durable cross-scan identity for a declaration grammar and must be collision-free by construction; condition 4 governs a *finding* fingerprint on a non-gating FACT, where the shipped finding-fingerprint machinery already tolerates bounded keys and a collision merges two adjacent diagnostics rather than corrupting an identity. Where P8's object is in play, P8 governs unchanged. That is computable for every value shape form 5 refuses, and deterministic across both readers — the two properties the fingerprint needs. **The distinctness claim is stated to match that preimage exactly**: two unreadable LEVEL arguments on one function are distinct whenever their argument names or their unparsed value texts differ, which the builtin registry's two distinct LEVEL keywords (`level=` on `@trusted`, `to_level=` on `@trust_boundary`) already give for the cross-marker case. What the preimage does **not** distinguish is two *stacked identical* decorators — the same keyword with the same value text, which `PY-WL-114` discriminates by a within-def ordinal and this key does not carry. That is the same bounded-key collision the truncation admits one sentence above, merging two adjacent diagnostics on a non-gating channel, and it is accepted on the same terms.
5. **Counted in `decorator_coverage`**, alongside `unknown_markers`, as a **seventh sibling summary key**. The shipped `summary` carries five (`total`, `clean`, `defect`, `unknown`, `suppressed`) and S0's unknown-marker work adds `unknown_markers` as the sixth; this FACT's count is the seventh, in the same shape as the sixth. **This specification fixes the derivation rather than minting a string**: the key is named from this rule id by the same rule that names `unknown_markers` from `WLN-ENGINE-UNKNOWN-MARKER`, it is accompanied by a report field mirroring `unknown_marker_count`, and **the same one name is used in all four places it surfaces** — the core summary dict, the MCP output schema, that schema's golden, and the CLI human renderer. It rides the **already-sanctioned** MCP-output-schema re-freeze that the sixth key requires and mints **no second re-freeze**; §12's per-kind rekey and `regen.py --reason` allowance is for new declaration kinds, and revision 6 introduces none. **Three populations, each counted once and never twice:** the channel is builtin-only, so a custom unreadable level value stays on `WLN-ENGINE-UNPROVABLE-BOUNDARY`; and the shape gate short-circuits, so a shape-malformed builtin call is counted as a `PY-WL-130` shape offence and never also as an unreadable value.

**The shape gate short-circuits, and the five conditions survive that ordering.** Where a builtin marker's call shape is malformed *and* its LEVEL value is unreadable, the site takes `PY-WL-130` only — the shared `call_shape_offences` verdict runs before any level is read, so the value reader is never reached and no FACT is emitted. The ordering is chosen because `PY-WL-130` is an ERROR DEFECT already firing loudly at that exact site and a `Severity.NONE` FACT stacked on it is noise rather than signal. **Neither channel dominates the other and this specification does not claim one does**: the shape channel gates but *is* suppressible, the FACT is unsuppressible but never gates, and a waived `PY-WL-130` leaves the site with nothing — which is acceptable only because suppressing it is an explicit, reviewed act against P13's fixed ceiling, not because the shape channel is strictly louder. The conditions hold as follows. **Condition 1** is untouched: the configuration rebuild erases a field that is simply empty at such a site. **Condition 2** is untouched: neither channel moves the posture denominator. **Condition 3** is untouched: it is a property of the FACT population, and a shape-malformed site is outside it. **Condition 4** is untouched: the two populations are disjoint by construction, so no fingerprint is contested. **Condition 5** holds *because* they are disjoint — that disjointness is the third population its no-double-counting clause now names.

**The FACT's carrier is a new field.** Both candidate carriers were barred — one by source, one by a delivery-plan directive the supersession list below now names. Reuse of `SeedResult.unprovable_boundaries` is barred **by source**: the provider documents that builtin boundary types never appear there — that exclusion is what preserves the byte-identity oracle — and the pipeline fingerprints those entries on `(rule, qualname, boundary)` alone, which cannot carry an `(argument name, value text)` pair. The repro is a **builtin** `@trusted`, so routing it there would violate the invariant and put P4's zero-byte-delta shipping gate (§2) at risk. Adding a new field was barred by plan line 1049's *"no `SeedResult` field, no `FunctionSeed` field"* clause, which this revision supersedes, together with that line's *"no `pipeline.py` change"* clause and nothing else in it — the *"and therefore no `SUMMARY_SCHEMA_VERSION` bump"* clause **stands** (see the supersession list below). Revision 6 therefore adds a **new `SeedResult` / `FunctionSeed` field, distinct from `unprovable_boundaries`** so that the builtin-exclusion invariant survives intact, carrying `(argument name, value text)` tuples through to the FACT emission loop.

**The field carries no serialised state, and `SUMMARY_SCHEMA_VERSION` does not move** (§4.3 owns the disposition). The reason is the measured behaviour of the engine rather than a judgement call, and it is written out here so it is not re-litigated on the wrong facts a third time: **the residual FACT is re-derived by the project parse pass's unconditional seeding on every scan, warm or cold, exactly as `WLN-ENGINE-UNPROVABLE-BOUNDARY` is, and therefore needs no serialised state.** Three measured facts fix that. First, **there is nothing to serialise the field into**: the summary cache stores tuples of `FunctionSummary` and nothing else — never a `FunctionSeed`, never a `SeedResult` — and the module summariser projects a seed down to body taint, return taint, taint-source class, unresolved-call count, schema version and cache key, dropping every other seed field at that boundary, `unprovable_boundaries` included. Second, **there would be nothing for a version bump to guard**: `SUMMARY_SCHEMA_VERSION` is `FunctionSummary.schema_version`, defined as moving whenever `FunctionSummary`'s structural shape changes, and a new seed-plane field does not change that shape. Third, **the warm-cache-loss premise is false**: the parse/seed loop runs the seeding pass unconditionally for every discovered module and consults the cache only to decide whether the module joins the dirty set that feeds the L3 resolver, while the seed-plane FACT emission iterates an **unserialised** `FunctionSeed` field inside that same loop — which is why the shipped sibling FACT already survives a warm cache with zero serialised state, and why the new one does too.

**Proposal, not settled — narrowing G2 to *silent* fail-open. This requires owner ratification and does not have it.** PRD-0003 criterion 2 reads the *count* of open known false-green holes at close and again at +30 days, so the residual FACT-only population has to be reconciled against that count rather than left to be argued at close. The reconciliation on offer is a **narrowing**: that G2 counts *silent* fail-open, so a value which stays unreadable after form 5 — dropping its seed **observably**, on a non-suppressible, counted, fingerprinted channel that configuration must preserve — is not an open false-green hole for criterion 2's purposes, because the hole G2 measures is the silence and not the seed drop. **PDR-0018 does not decide this.** That record decides the widened reader and the residual FACT, and it carries this question in its own words as an **UNRATIFIED PROPOSAL** reserved to the owner; nothing downstream may cite it as decided, and §4.2.1 does not rely on it — every other obligation in this section stands whichever way it is ruled. The argument is recorded on both sides so the ruling is made on the whole of it:

- **For the narrowing.** PRD-0003 :92-94 puts a residual unreadable population — calls, f-strings, runtime config lookups — outside **this bet's** scope **by design**; those lines sit under the heading `## Non-goals (this bet)` and say nothing about permanence, so the premise is bet-scoped and is stated that way here. Criterion 2 read literally is therefore unsatisfiable **within this bet's scope**: for as long as this bet's scope holds, there will be a value the reader cannot resolve. And PRD-0003 :107-109 asks for precisely what the residual delivers — that a value the widened reader still cannot resolve "fail[s] closed and take[s] a diagnostic channel". On that reading the residual is the constraint being *met*, not a hole left open.

Nothing was silent there. G2's operative test as applied in that reading was whether the **gate's colour matched reality**, not whether anything appeared in the output — and by that test a residual whose seed has dropped is a hole no matter how loudly it is narrated, because the gate is green over code the engine did not check.

### 4.4 Rust

No new markers, no doc-comment recognition of the new vocabulary, and **`rust/vocabulary.py`'s legal sets are unchanged** — the Rust frontend can neither declare nor mint restoration states (a widened Rust legal-return set would let `rust_taint.yaml` mint unwitnessed `UNKNOWN_*` states; refused). A `WLN-RUST-COVERAGE` note names the asymmetry. Cross-language propagation stays governed by §10.5 of the as-built spec.

**The shipped Rust marker's shape channel closes in this programme (revision 6).** No new vocabulary is involved. A doc-comment marker in the *existing* Rust surface whose shape is non-canonical today silently fails to match: the declaration is discarded, the function leaves the declared set, and the gate goes green with no diagnostic on any channel — the same false-green class as §4.3's Python call-shape hole, in the same fail-open direction (`wardline-b857b50b54`; PRD-0003 criterion 6, which is unmet regardless of the Python result if the Rust frontend is left out). The fix is a **two-stage recognise-then-parse split** reusing the frontend's existing failure path: recognition widens so a non-canonical marker is *seen*, and parsing then rejects it through the path that already exists, so an unreadable marker fails loudly instead of being missed silently.

**The widened recogniser is specified as a recogniser, a refusal set and an upper bound — enough to write the pattern from this text alone.** The shipped `_MARKER` in `src/wardline/rust/provider.py` is `re.match`-anchored with a leading `\s*`, requires the literal `@trusted`, then an opening parenthesis, then the literal keyword `level`, an `=`, a bare word captured as the level, and a closing parenthesis, with optional whitespace already tolerated around the marker name, each parenthesis and the `=`. Two consequences follow and the previous draft got both wrong: **whitespace variants are already accepted today** and are not part of the widening, and the shapes that actually fail are the ones inside the parentheses.

- **Recogniser.** Widening is confined to the **argument list**. The recogniser matches, anchored at the start of the doc-comment text after optional whitespace, the literal `@trusted`, optional whitespace, and a parenthesised group whose contents it **captures verbatim and does not interpret**, up to the **first** closing parenthesis. It is the first and not the *matching* one: matching requires balancing, which the recogniser explicitly disclaims, so no balancing rule is stated or implied. A nested parenthesis therefore truncates the captured group; recognition still succeeds, and acceptance is decided at the parse (below). The shipped pattern is not end-anchored and the widened one does not become so; only the argument list changes. Every family in `wardline-b857b50b54` falls out of that one change: a **quoted** value (`level="ASSURED"`), an **extra keyword** beyond the canonical one (`level=ASSURED, audit=true`), a **wrong keyword name** (`tier=ASSURED`), an empty argument list, and the whitespace variants of each. `wardline-b857b50b54` carries the full observed shape list; this shape is the floor.
- **Refusal set — what must still not match.** The **anchor stays**: recognition is `match` at the start of the doc text, never `search`, so a marker mentioned in prose ("do not use `@trusted(level=ASSURED)` here") is still not a marker — a `search` would falsely seed trust and spuriously un-suppress the function's findings, which is the reason the anchor exists. The **marker token is not widened**: recognition still requires the exact token `@trusted`, so `@trust`, `@trustedly` and every other name stay unrecognised — a name outside the vocabulary is not an attempted trust marker, and widening the name would mint a recogniser for a vocabulary that does not exist. And a `@trusted` with **no parenthesised argument list at all** stays unrecognised, exactly as today; the Rust surface has no bare marker form and revision 6 does not add one.
- **Upper bound.** Those three refusals *are* the upper bound: the anchor, the exact marker token, and the requirement of a parenthesised argument list are unchanged from the shipped pattern, and the widening reaches nothing else. Recognition is also still per doc-comment line, reading one line's text as the shipped recogniser does.

Recognition succeeding is not acceptance: every widened shape then fails the parse.

**The recogniser-hit-but-parse-miss path raises an existing diagnostic; no new rule id is minted.** The parser signals the failure by raising `ValueError`, which the entity loop's existing `except ValueError` around `taint_for` converts through `_invalid_trust_marker_finding` into **`WLN-ENGINE-RUST-INVALID-TRUST-MARKER`** (ERROR DEFECT, `src/wardline/rust/analyzer.py`), keeping the function's fail-closed tier while emitting a gate-eligible diagnostic at the offending callable. That is exactly the behaviour the false green lacks: today the marker is never recognised, so the failure path is never entered. **Recognition widening is not vocabulary widening** — `rust/vocabulary.py`'s legal sets stay exactly as stated above, and the Rust frontend still can neither declare nor mint restoration states. Blast radius is measured rather than assumed: all 21 markers in the frozen Rust fixtures use the canonical form, so the widened recogniser flags no frozen fixture — a measurement taken against the in-tree fixtures only, and re-confirmed at implementation.

**Two further cases have stated answers, because §4.4 now stands without a delivery-plan task beside it.** First, **multiple markers on one callable.** `_declared_level` walks the contiguous run of preceding `line_comment` / `attribute_item` siblings **backwards from the `fn`** and returns on the first marker it recognises — the one *nearest* the callable — and that walk is unchanged by the widening. It decides the mixed case by itself: given a canonical marker and a non-canonical one on the same callable, the nearer is recognised first, and if that is the non-canonical one the parse raises and the walk **stops** rather than falling through to the canonical sibling above it. **First-recognised-wins, and a recognised-but-unparseable marker is never overridden by a canonical sibling** — the fail-closed direction, and the only one consistent with the point of the change. Second, **the diagnostic's `detail` text.** No new rule id is minted, so every rejection shares `WLN-ENGINE-RUST-INVALID-TRUST-MARKER` and the finding's fingerprint does not carry `detail`; the text is therefore the only discriminator between malformations, in output and in a test. It must **name the shape family that was rejected**, drawn from the families enumerated in the recogniser bullet above — a quoted value, an extra keyword, a wrong keyword name, an empty argument list — alongside the shipped invalid-level case, in the spirit of §4.2's stable Python reason vocabulary.

**Ownership: this is a separate thread, not an S0 task (owner ruling, 2026-08-10; §13.2).** The two halves of PRD-0003's false-green work were split because only the Python half re-cuts S0's engine core: revision 6 places form 5 inside the shared reader's produced interface and its P9 receipt, so `wardline-2b2a6cddfa` cannot be additive work alongside a green S0 and stays inside it. ### 5.2 The label algebra (normative)

Each tracked variable carries exactly one label state; the algebra is the whole story of what WL-001 may conclude:

| State | Meaning | Introduced by | WL-001 verdict at an access site |
|---|---|---|---|
| `ABSENT` | no declaration anywhere | default | **silent** — the opt-in sentinel |
| `VALID{c}` | exactly one resolved contract | a readable `@schema` boundary; survives copy/`Await`/`Starred`/labelled-call-return | adjudicate per §5.3 |
| `POISON` | conflicting or partial-arm labels (branch union with disagreement; two different contracts merged) | `_merge`-style union on branch joins; any multi-label set | **silent**, but distinguishable: surfaced via `explain_taint` and counted in a `WLN-ENGINE-LABEL-POISON` FACT |
| `UNREADABLE` | a declaration **exists** but could not be honoured (unresolvable/ambiguous/rebound/shadowed reference; partially-readable contract; duplicate FQN) | the boundary whose `@schema` matched but failed to read; propagates exactly as `VALID` does | **fires at base severity** (the fail-closed direction: the author claimed a contract; the engine cannot honour it, so every defaulted access on that source is an undeclared default) + `WLN-ENGINE-UNREADABLE-CONTRACT` FACT naming the reference |

Merge rules: `ABSENT` is the identity; `UNREADABLE` absorbs `VALID` and `POISON` (a partially-honoured source must not be quieter than an honoured one); `VALID{a}` ∪ `VALID{b}` (a≠b) = `POISON`; `POISON` ∪ `VALID` = `POISON`. All four states are monotone under union with this ordering (`ABSENT < VALID < POISON < UNREADABLE`), which is what the L2 fixed point needs (§5.4). Every aggregation and value-merge resets to `ABSENT` (mapping-level identity only — the honest FN, counted in a FACT).

### 5.3 Rule semantics — `PY-WL-127` (WL-001)

Fires at `d.get(k, default)` / `d.pop(k, default)` where the receiver's label is `VALID{c}` (or `UNREADABLE`, per §5.2), `k` is a literal string, and the default is statically readable (94.8% measured):

| Declared state of `k` in `c` | Code | Verdict |
|---|---|---|
| `Field.REQUIRED` | any default | **ERROR** — absence is an integrity failure; fabricating a value converts it to silent corruption |
| `Field.default(v)` | code default ≠ `v` | **ERROR**, distinguished as a policy contradiction (`contradiction` property) — fingerprint carries the declared default (§5.5). Outranks the undeclared case; `CRITICAL` stays operator-override-only |
| `Field.default(v)` | code default == `v`, lexically inside a declared validation boundary | **INFO** — downgraded, never removed (D1/P2) |
| `Field.default(v)` | code default == `v`, outside a boundary | **WARN** |
| `Field.OPTIONAL_EXPLICIT` | any default | **ERROR** — absence must be represented, never substituted |
| field not in contract | any default | **WARN** — the contract had no opinion on this field |
| *(receiver `UNREADABLE`)* | any default | **ERROR at base** — undeclared-default posture, per the algebra |

- A field carrying a sensitivity mark (§6) can never be downgraded below its base — the per-field no-escape policy.
- `.setdefault` is a distinct finding shape (it writes the fabrication back; every downstream reader inherits it).
- **Modulation anchors on the contract, not the enclosing tier** (verified necessity: enclosing-tier modulation silences the rule in `@external_boundary` functions — the flagship example's home). The mechanism is the shipped `enclosing_declared_tier` pattern with a contract-declared set; opt-in is preserved because the contract *is* the opt-in.
- `d[k]` (`KeyError` semantics) is never a finding — absence raises, which satisfies `REQUIRED`.
- Named accepted FNs, counted in FACTs: non-literal keys (~24% of default-carrying sites), `try/except KeyError: return default` (paired detection is a fast-follow), aggregation-severed labels, chained-attribute receivers, dict unpacking.
- Worked call-boundary example (carried in rule metadata): `order = fetch_order(req)` then `order.get("order_id", 0)` fires — `fetch_order`'s return label enters `function_return_contracts` via the L2 fixed point, the assignment copies it, the `.get` site sees `VALID{ORDER_CONTRACT}`. Same through `await`.

`PY-WL-128` (WL-002): existence-probing (`k in payload` as a gate) on a `REQUIRED` field — same reader, same algebra, ships with 127.

## 6. Kind 2 — sensitivity marks (same stage as contracts)

Sensitivity has **two attachment points**, matching what each consumer needs:

1. **Per-field, inside the contract** — `Field.default("OFFICIAL", sensitivity=(...,))` / `Field(required=True, sensitivity=…)`. This is what the WL-001 no-downgrade policy reads (§5.3), and the disclosure rules read at field-access sites on contracted sources.
2. **Per-function return** — `@sensitive(marks=(Sensitivity.PII,))` marks a function's whole return value; the mark rides the same value-label side-channel.

Model, resolved: **categories with union**. Marks are an unordered set of project-defined category tokens (`Sensitivity.of("classification")`, or project packs may mint tokens); merge is set-union (conservative for disclosure — a value that might carry a credential is treated as carrying it). There is no ordinal ordering and no "maximum". Category names are project-defined; wardline ships no classification scheme and Australian ISM names never appear as wardline-defined vocabulary.

**Unmarking has no mechanical power.** There is no `NOT_SENSITIVE` state that silences anything — that would be a repo-authored exemption, violating P1/P2. Absence of a mark is just absence; the declarations ledger records what is marked, and the coverage FACT (an unmarked value reaching a disclosure sink from a contracted source) is what makes non-marking visible. If a future need for attested non-sensitivity emerges, it is a record-only token and any consumption of it is caller-granted (P1).

Consumers in this stage: severity escalation on the disclosure-adjacent sinks (log content — complementing PY-WL-125's injection focus — exception/error-response construction, SMTP), the WL-001 per-field policy, and the coverage FACT. Redaction idioms (hash/prefix logging) are sentinels.

## 8. Kind 4 — restoration boundaries (last engine stage)

### 8.1 Semantics — the normative evidence→state table (v1)

The author declares **evidence, never a level** (`to_level` does not exist on this marker). v1 admits **only evidence the L1 provider can verify body-locally at seed time** — the provider holds the decorated function's AST when it seeds, so a body walk is available; nothing else is (§8.2).

| Evidence category | v1 verification | Uplift contribution |
|---|---|---|
| `STRUCTURAL` | **body-local**: a genuine rejection path in the decorated body (the PY-WL-102/119 predicate, run at seed time) | base requirement for any uplift |
| `INTEGRITY` | **body-local**: a verify-shaped call (hmac/signature/digest-compare set) in the decorated body with a rejection path reachable from its failure (the PY-WL-113 fail-open predicate, inverted) | the step from `UNKNOWN_GUARDED` to `UNKNOWN_ASSURED` |
| `SEMANTIC` | **none exists** — no static predicate distinguishes "the right domain constraint" from "a shape check"; the as-built spec says so (§3, §9.1). **Record-only in v1**: ledger entry, zero uplift | none |
| `INSTITUTIONAL` | not verifiable by any tool (D2). **Record-only**: ledger entry, zero uplift; future caller-granted consumption possible, none ships | none |

| Declared, verified evidence | Resulting seed |
|---|---|
| ∅, or `STRUCTURAL` claimed but not verified | no uplift — fail-closed `EXTERNAL_RAW` seed + a lineless engine-path DEFECT (`WLN-ENGINE-UNPROVABLE-RESTORATION`) — a bare or unbacked assertion buys nothing, loudly, and gates |
| `STRUCTURAL` verified | `UNKNOWN_GUARDED` (rank 4) |
| `STRUCTURAL` + `INTEGRITY` verified | `UNKNOWN_ASSURED` (rank 3) — **the program ceiling** |

Unbacked evidence yields zero uplift, not partial (degrading a shotgunned claim rewards over-claiming). This table gives every uplift step a **distinct machine-verified predicate** — the structural step and the integrity step verify different things, and the two unverifiable categories verify nothing. The 16-row evidence-vector pin reduces in v1 to this table plus record-only entries; the unit test pins all rows.

**Deferred design (v2, recorded not built):** a pre-L3 verification phase that re-derives restoration seeds after call resolution, enabling one-hop helper recognition (validator/verifier in another function) and possibly a `SEMANTIC` predicate. It requires seeds that can be *revised downward* between L1 and L3 with cache-correct invalidation — a real architecture change, not a bolt-on, which is exactly why v1 is body-local.

### 8.2 Why body-local: the seeding-order constraint

Seeding happens per-file at parse time, before the project call graph or any rule context exists. A one-hop helper check therefore *cannot* inform the seed without a new phase. v1 restricts the grammar to what the provider can prove from the decorated body alone — the same place `LevelArg` reading already happens — so verification and seeding are simultaneous and the seed is final. No verified-later-revised-earlier machinery, no ordering hazard.

## 11. Evidence, attestation, and the legis seam

### 11.1 The declarations inventory (one factory, three consumers)

Every declaration emits `{declaration_id, kind, content_digest, verification_class, subject, sei?}`:

- **`declaration_id` is tool-independent and deterministic**: `sha256("wlds1" ‖ kind ‖ subject ‖ field?)` where `subject` is the scan-root-relative qualname (functions) or contract FQN (contracts) or table key (dependency entries). **SEI is optional metadata alongside, never the id** — an id must not change because optional Loomweave enrichment came or went. A rename changes the id (as it changes fingerprints today); continuity across renames is legis's re-binding concern, not wardline's.
- **`content_digest`**: SHA-256 over a canonical encoding — sorted keys, type-tagged scalars (so `"1"` ≠ `1`), NFC-normalised strings, evidence/marks in their declared canonical order, defaults as their canonical literal text. Reformat-stable (whitespace/comment changes don't churn it), value-change-sensitive.
- **`verification_class`** ∈ `{machine_verified, structurally_verified, recorded_unverified}` per element.

One factory builds it; attest, assure/dossier, and the legis artifact consume it (the `gate_decision()` no-drift precedent).

### 11.2 Attest — one schema break (`wardline-attest-3`), consumer-first

Carries: the sorted `declarations[]` ledger; per-kind `declaration_counts`; declaration debt in the posture (lapsed `expires`, stale dependency pins, record-only claims); the payload-resident HMAC disclaimer + git-as-authorship framing (D3); legible grant-state fields (`trusted_packs`, `trust_dependency_taint`, `strict_defaults`) and the dependency-table digest.

**Rollout and verification profiles:** consumer preparation is S0; the declaration-bearing attest-3 producer and emission remain S1. S0 authors a DRAFT, non-normative attest-3 contract and signed preview vector. The key-holding Wardline verifier dual-accepts attest-2 and attest-3 and reports `schema_recognized` independently from `signature_valid`; `signature_valid` may be true only for a recognised schema with a valid HMAC. A missing or unknown schema sets both fields false, including when the bundle was correctly re-signed over its own unknown schema tag. Attest-2 continues to verify and attest-1 remains rejected.

Warpline is a non-key-holding consumer of pushed, untrusted bundles. It accepts attest-2 and attest-3 for schema, commit/tree, Stable Entity Identity (SEI), verdict, and current-content checks, but never performs runtime HMAC verification and always reports `signature_verified: false`; its `source` names the schema actually consumed. Independent HMAC derivation with the public test-vector key is conformance-only. Wardline owns the preview vector and Warpline vendors it byte-identically. S1 compares its first real attest-3 serialization semantically and bytewise with the preview before replacing and freezing it.

### 13.3 Rollout gates

The local-coordination and published-release gates are cumulative and not interchangeable.

- **Local coordination:** the consumer task commits are ancestors of their designated integrated branches; cold installs are built from archives of those recorded heads rather than dirty checkout bytes; installed-package probes and both cross-repository receipts pass; long-running federation processes are restarted. Passing this gate permits local S1 development and coordinated local emission only.
- **Published emission:** before any published Wardline release emits generic-3 or attest-3, published Loomweave, Warpline, and Legis releases must contain the recorded consumer commits. The exact published distributions are cold-installed and probed, vector receipts are rerun against archives of the exact release tags, tag/version/commit and distribution-hash evidence is recorded, and the release-train owner authorizes emission. S0 performs no consumer release bumps and closes with `published_emission_ready=false`.
- **S1 producer preflight:** the first real generic-3 and attest-3 outputs are compared semantically and bytewise with their non-normative previews before the previews are replaced and the producer formats are frozen.
- **Rollback:** revert the Wardline producer first so emission returns to generic-2/attest-2. Leave surplus consumer dual-acceptance deployed; never revert consumers while a producer still emits the new formats.

## 14. Rejected alternatives

- **Positional/bare-name marker syntax** (`@schema(ORDER_CONTRACT)`) — violates the reader's fail-closed grammar and `PY-WL-130`; keyword-only `contract=` with `RefArg` is the lawful form (rev-2 correction).
- **Cross-module resolution of P3 form 5 value references** (rev 6) — refused, and deliberately recorded **here** rather than as a scheduled later widening, because "later widening" reads as approved-in-principle and invites an implementer to ship it without re-deriving the cache obligation. Two independent facts decide it. **Cache:** the summary cache key length-prefixes only the analysed module's own source bytes alongside the schema, resolver and provider versions and the policy hash — nothing about any other module — and the dirty frontier is a transitive-caller closure over CALL edges, which a constant is not; module A's constant could therefore change without invalidating module B's warm summary, a stale false green of exactly the class form 5 exists to close, and structurally unobservable to the only guard that exists. **Determinism:** project parsing is one sequential pass in which a module is parsed and seeded inside the same iteration, so at the moment a LEVEL is read no other module's AST exists; cross-module resolution would make the seed depend on parse order and on scan scope, and `wardline scan src/` and `wardline scan .` could disagree about whether a boundary is declared. **Named reopening precondition:** referenced constants become a tracked dependency edge in the dirty frontier, **or** the cache key absorbs the bytes of every referenced constant. Absent one of those two, this stays rejected.
- **The enclosing-scope walk for P3 form 5 reference sites** (rev 6) — refused in favour of the tighter cut, which is that form 5 applies only when the decorated `def` / `async def` is a direct element of the module body (§4.2.1). Walking outward from a method or a nested `def` / `async def` to find the binding Python would actually evaluate is the *correct* semantics, and that is exactly why it is dangerous here: it needs its own case table — class body versus enclosing function body versus comprehension scope versus a `nonlocal` write — and every additional row is another place an implementer's guess becomes a false green, which is how this defect arrived. **The refusal that this bullet records is the scope-walk refusal, and it is not the whole of the restriction.** §4.2.1's cut is drawn one notch tighter than the scope argument reaches: a `def` or `async def` nested inside a module-level `if` or `try` introduces **no new scope**, so nothing in the paragraph above argues against it, yet form 5 refuses it anyway — for the independent reason that the binding site's own discipline is "direct top-level, unconditional" and the reference site is held to the same sentence rather than to a second, looser one that could drift from it. **Measured cost of the scope-walk refusal, recorded so it is not re-derived:** of the 72 marker call sites carrying `level=` / `to_level=` in this repository, **6** sit on methods or nested defs, and the repo-wide census found **zero** bare-`Name` level values anywhere. That restriction costs nothing today. **The 72/6 reading covers the scope-walk cut and nothing else, and must not be read as covering the conditional-`def` cut**: the census counted methods and nested defs, and recorded **nothing** about how many module-level `def` / `async def` statements sit inside an `if` or `try` — that population is unmeasured, so no cost figure for it exists in this document or anywhere behind it. **The conditional-`def` cut is therefore taken on the fail-closed argument alone.** **Named reopening precondition, covering both cuts:** a *measured* population of nested, method, or conditionally-defined `def` / `async def` statements that want form 5 — not an anticipated one.
- **Undeclared kwargs on level-bearing markers** — verified silent seed-drop under version skew. Declared runtime kwargs such as `@trusted(level=...)` and `@trust_boundary(to_level=...)` remain lawful.
- **Dotted-string contract references** — a second namespace with no import error, no rename safety, no mypy.
- **Contracts as trust-grammar packs** — packs are granted code-execution artefacts; contracts are per-app data; behind `--trust-pack` the flagship rule is off by default.
- **Contracts in `weft.toml`** — the designed manifest reborn; forfeits same-diff review and recreates the poisoning surface.
- **Designed approved-default suppression** (D1) — upstream of the unsuppressed-population split; mismatch-escalation is inert under agent authorship.
- **Institutional or semantic evidence as uplift inputs** (D2, rev 2) — no distinct machine predicate exists for either; an unverifiable assertion must not raise trust from source.
- **One-hop evidence checks at seed time** (rev 2) — seeding precedes call resolution; needs the deferred pre-L3 verification phase, not a bolt-on.
- **Restoration reaching `ASSURED`/`GUARDED` from a bare declaration** — capped at `UNKNOWN_ASSURED`; the caller-grant route is also the only cross-frontend-consistent uplift mechanism.
- **Widening Rust legal-state sets** (rev 2) — would let `rust_taint.yaml` mint unwitnessed restoration states.
- **Ordinal sensitivity with max-merge, and silencing `NOT_SENSITIVE`** (rev 2) — categories are unordered (union), and unmarking must not be a repo-authored exemption.
- **SEI as primary declaration id** (rev 2) — availability-dependent identity makes declarations appear deleted/recreated when optional enrichment changes.
- **`reviewed_by` in dependency entries** (rev 2) — reviewer identity is governance; git/legis own who.
- **Single big-bang weft-markers 0.2.0** (rev 2) — staged exports so no marker ships before its consuming rule.
- **Widening `var_taints` / labels in `FunctionSummary`** — the side-channel keeps `least_trusted` untouched by construction and the cache label-free (witness excepted, §8.3).
