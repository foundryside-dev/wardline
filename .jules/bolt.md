## 2026-06-21 - Avoid Eager List Materialization in AST Traversal
**Learning:** In the `wardline` static analyzer, AST traversal functions (like `_walk_body`, `_collect_return_paths`, etc.) frequently iterated over generator objects produced by `ast.iter_child_nodes()` or node attributes like `func_node.body` by eagerly converting them into lists via `list(...)`. Because these recursive functions map across large, deeply-nested AST structures, the intermediate list allocations induce significant unnecessary memory overhead and garbage collection pressure, negatively impacting performance. Since the traversal logic performs a single pass without mutating the collections, materializing lists is entirely redundant.
**Action:** When implementing or modifying AST traversal functions, type them to accept `Iterable[ast.AST]` (or `Iterable[ast.stmt]`) and pass generators (like `ast.iter_child_nodes()`) or lists (like `func_node.body`) directly instead of eagerly materializing them. This eliminates intermediary list allocations, adhering to Python performance best practices while preserving semantics.
