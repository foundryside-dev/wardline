## 2024-10-24 - AST Traversal Optimization with Explicit Stack
**Learning:** For hot-path AST traversal, use an explicit stack combined with `yield` instead of `yield from` recursion to preserve lazy evaluation and short-circuiting capabilities. Avoid eager list-appending (`list.append()`) to prevent computing the whole subtree when early matches exist. Reverse child nodes via `reversed()` before extending the stack to preserve traversal order. When handling multiple attribute groups for a node (e.g., a ClassDef's keywords, bases, and decorator_list), push the groups themselves onto the stack in the reverse order of intended traversal so they are popped and processed correctly. When initializing explicit AST stacks from sequences like `node.body`, explicitly annotate the type as `list[ast.AST]` (e.g., `stack: list[ast.AST] = ...`) to prevent mypy type inference errors. Iterating through `current._fields` in reverse order inside the explicit stack logic is faster than using `ast.iter_child_nodes`. Critically, use `isinstance(node, ast.NodeType)` instead of `type(node) in (...)` to ensure Mypy can correctly type-narrow specific node attributes (e.g., `.args`), and retain `isinstance(node, ast.AST)` checks to prevent `AttributeError`s when traversing `_fields`.
**Action:** Replace `yield from` recursive AST traversal with explicit stack-based iteration using `reversed()` and explicit attribute checks for hot-path AST traversals.
