## 2026-06-21 - AST Traversal Generator Overhead
**Learning:** In hot-path AST traversal functions (`iter_calls_in_function_body`), recursive generators using `yield from` combined with `ast.iter_child_nodes` carry a significant performance penalty compared to an explicit stack. A subtle gotcha when converting to an explicit stack: when a node has multiple attribute groups (like `ClassDef` with keywords, bases, and decorator_list), you must push the groups onto the stack in the *reverse* order of their intended traversal, so that the stack pops them in the correct forward order.
**Action:** When optimizing recursive AST functions to iterative ones, manually traverse `node._fields` in reverse, append to a stack, and pay careful attention to the stack push order for composite nodes to preserve correct traversal order.
